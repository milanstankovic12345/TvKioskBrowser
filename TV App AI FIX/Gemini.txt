This is a common progression of issues when migrating legacy WebView behavior to modern Android versions. Android 9 (Pie) and Android 11 (R) introduced strict security updates regarding network traffic, process isolation, and background activity management.
Here is the detailed technical breakdown of why your app is failing and the specific code changes required to fix it.

1. The Android 9 & 11 "Immediate Crash" or Network Failure
The Cause: Cleartext Traffic Policy (HTTP vs. HTTPS)
Starting with Android 9 (API 28), the system forbids "Cleartext" (unencrypted HTTP) traffic by default.
On Android 9: The WebView might load a blank page or throw an error, which can lead to a crash if your error handling logic tries to reload immediately in a loop.
On Android 11: Strict enforcement can cause the app to crash immediately if the WebView attempts to initialize a resource (like a favicon or API call) over HTTP during onCreate.
The Fix: You must explicitly allow Cleartext traffic in your AndroidManifest.xml.
XML
<application
    android:label="@string/app_name"
    android:icon="@mipmap/ic_launcher"
    android:usesCleartextTraffic="true"  ...>
    ...
</application>


2. The Android 9 "Crash After Reboot"
The Cause: WebView Data Directory Conflict
This is the most likely culprit for the "works once, then crashes on reboot" behavior.
In Android 9, WebView implementation changed how it handles data directories. A WebView cannot share the same data directory across multiple processes.
If your app uses a Boot Receiver or a Background Service (to handle the refresh timer) that runs in a separate process from your main UI Activity, and both try to access the WebView (or CookieManager), the app will crash with a RuntimeException.
Why it happens on reboot: On the first install, you likely open the Activity manually. On reboot, your BroadcastReceiver (background process) starts first, initializes the WebView logic, and then tries to launch the Activity (UI process). Both processes collide over the data folder app_webview.
The Fix: You must define a unique suffix for the WebView data directory in any process that is not the main process. Add this to the onCreate of your Application class or your Service.
Java
// Inside your Application class or Service onCreate
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) {
    String processName = getProcessName(); // Utility method to get current process name
    if (!getPackageName().equals(processName)) {
        // If this is not the main process, set a suffix
        WebView.setDataDirectorySuffix("background_process");
    }
}


3. The Android 11 "Crash on Launch" (Background Restrictions)
The Cause: Background Activity Start Restrictions
Android 10 and 11 introduced heavy restrictions on starting Activities from the background.
The Scenario: Your app listens for BOOT_COMPLETED. When the device boots, your BroadcastReceiver runs (in the background) and tries to call startActivity() to open the browser.
The Result: Android 11 blocks this call. If not handled, it throws an exception. If you use a specific Hisense intent, the OS might kill the app for violating foreground rules.
The Fix: You must grant the app the SYSTEM_ALERT_WINDOW permission (Display over other apps) or use the Full-Screen Intent notification approach.
Step A: Update Manifest
XML
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>

Step B: Handle the Permission Logic For a commercial display, you usually cannot ask the user to grant permissions manually. However, since you likely have ADB or root access (or it's a signed system app), you can grant this via ADB: adb shell appops set <your.package.name> SYSTEM_ALERT_WINDOW allow
Step C: Update Boot Receiver Logic In your BootReceiver.java:
Java
@Override
public void onReceive(Context context, Intent intent) {
    if (Intent.ACTION_BOOT_COMPLETED.equals(intent.getAction())) {
        Intent i = new Intent(context, MainActivity.class);
        i.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
        
        // Required for Android 10+ (Q/R)
        // Note: This only works if you have the "Display over other apps" permission granted
        context.startActivity(i); 
    }
}

Executive Summary

The application failures on Android 9 and 11 stem from the evolution of Android's security model, specifically Background Activity Start Restrictions (introduced in Android 10) and Cleartext Traffic Blocking (Android 9).

    Android 9 Crash: Caused by stricter power management killing the app's process during "HDMI standby" (which isn't a true reboot) and potential WebView data directory conflicts in multi-process contexts.

    Android 11 Crash: Caused by the system blocking the BOOT_COMPLETED receiver from launching an Activity directly. Without the SYSTEM_ALERT_WINDOW permission or a "Foreground Service Bridge," the OS silently blocks or crashes the launch attempt.

The solution below implements a Foreground Service Bridge to satisfy Android 11's background start requirements and adds specific Manifest flags to bypass security restrictions on Hisense firmware.

Root Cause Analysis

Feature/Issue	Android 7 (Nougat)	Android 9 (Pie)	Android 11 (R)
Boot Behavior	Allowed direct Activity launch.	Restricted. Background apps usually cannot start Activities.	Blocked. Throws BackgroundServiceStartNotAllowedException or fails silently.
Network Security	HTTP allowed by default.	HTTP Blocked. Requires usesCleartextTraffic="true".	HTTP Blocked. Strict enforcement.
WebView	Shared data directory allowed.	Process Isolation. Multi-process usage of WebView requires distinct data directories.	Strict Isolation. Renderer process crashes can kill the entire app.
Hisense Firmware	Standard Android behavior.	Aggressive Kill. Kills background processes to save memory; "Power Off" is often just "Deep Sleep."	Launch Blocking. May ignore BOOT_COMPLETED if app is not "Device Owner."

2. The "Bridge" Service (KioskService.java)

Why: Android 10+ forbids BootReceiver from starting an Activity directly. The Receiver must start a Foreground Service first. This Service then acquires "foreground" privilege and launches the Activity.
Java

// File: app/src/main/java/com/yourcompany/kiosk/KioskService.java
package com.yourcompany.kiosk;

import android.app.Notification;
import android.app.NotificationChannel;
import android.app.NotificationManager;
import android.app.Service;
import android.content.Context;
import android.content.Intent;
import android.os.Build;
import android.os.Handler;
import android.os.IBinder;
import android.os.Looper;
import android.provider.Settings;
import androidx.core.app.NotificationCompat;

public class KioskService extends Service {
    private static final String CHANNEL_ID = "KioskChannel";
    private static final int NOTIF_ID = 1;

    @Override
    public void onCreate() {
        super.onCreate();
        startForeground(NOTIF_ID, createNotification());
    }

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        // Cursor: Delay launch slightly to ensure system readiness on Hisense
        new Handler(Looper.getMainLooper()).postDelayed(this::launchKioskActivity, 2000);
        return START_STICKY;
    }

    private void launchKioskActivity() {
        // Check overlay permission for Android 10+
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M) {
             if (!Settings.canDrawOverlays(this)) {
                 // Log error: Permission required for 100% reliable background starts
             }
        }

        Intent activityIntent = new Intent(this, MainActivity.class);
        activityIntent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
        activityIntent.addFlags(Intent.FLAG_ACTIVITY_REORDER_TO_FRONT);
        // CRITICAL: Required for Android 10+ to acknowledge this as a user-facing action
        activityIntent.addFlags(Intent.FLAG_ACTIVITY_NO_ANIMATION);
        
        try {
            startActivity(activityIntent);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    private Notification createNotification() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            NotificationChannel channel = new NotificationChannel(
                    CHANNEL_ID, "Kiosk Service", NotificationManager.IMPORTANCE_LOW);
            getSystemService(NotificationManager.class).createNotificationChannel(channel);
        }

        return new NotificationCompat.Builder(this, CHANNEL_ID)
                .setContentTitle("Kiosk Active")
                .setContentText("Keeping display active...")
                .setSmallIcon(R.mipmap.ic_launcher)
                .setPriority(NotificationCompat.PRIORITY_LOW)
                .build();
    }

    @Override
    public IBinder onBind(Intent intent) { return null; }
}

3. BootReceiver.java

Why: Detects the boot signal and delegates to the Service.
Java

// File: app/src/main/java/com/yourcompany/kiosk/BootReceiver.java
package com.yourcompany.kiosk;

import android.content.BroadcastReceiver;
import android.content.Context;
import android.content.Intent;
import android.os.Build;

public class BootReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {
        String action = intent.getAction();
        if (Intent.ACTION_BOOT_COMPLETED.equals(action) || 
            "android.intent.action.QUICKBOOT_POWERON".equals(action) ||
            "com.htc.intent.action.QUICKBOOT_POWERON".equals(action)) { // Hisense specific

            Intent serviceIntent = new Intent(context, KioskService.class);
            if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
                context.startForegroundService(serviceIntent);
            } else {
                context.startService(serviceIntent);
            }
        }
    }
}

// File: app/src/main/java/com/yourcompany/kiosk/MainActivity.java
package com.yourcompany.kiosk;

import android.os.Bundle;
import android.os.Handler;
import android.os.Looper;
import android.view.View;
import android.view.WindowManager;
import android.webkit.WebSettings;
import android.webkit.WebView;
import android.webkit.WebViewClient;
import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {
    private WebView webView;
    private final Handler handler = new Handler(Looper.getMainLooper());
    private static final String TARGET_URL = "https://your-url.com"; // TODO: Set URL
    private static final long REFRESH_DELAY = 60 * 1000; // 60 seconds

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        
        // 1. Keep Screen On (Hisense fix)
        getWindow().addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON);
        
        // 2. Fullscreen Immersive
        hideSystemUI();
        
        setContentView(R.layout.activity_main);
        
        // 3. Initialize WebView safely
        webView = findViewById(R.id.webview); // Ensure ID matches XML
        setupWebView();
        
        if (savedInstanceState == null) {
            webView.loadUrl(TARGET_URL);
        }
        
        startAutoRefresh();
    }

    private void setupWebView() {
        WebSettings settings = webView.getSettings();
        settings.setJavaScriptEnabled(true);
        settings.setDomStorageEnabled(true);
        
        // Fix for Android 9+ (Mixed Content / HTTP)
        if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.LOLLIPOP) {
            settings.setMixedContentMode(WebSettings.MIXED_CONTENT_ALWAYS_ALLOW);
        }

        webView.setWebViewClient(new WebViewClient() {
            @Override
            public boolean onRenderProcessGone(WebView view, android.webkit.RenderProcessGoneDetail detail) {
                // Fix for Android 11 renderer crashes
                if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.O) {
                    if (!detail.didCrash()) {
                        // Renderer killed by system for memory -> Just reload
                        webView.reload();
                        return true;
                    }
                }
                // Actual crash -> Restart Activity
                recreate();
                return true;
            }
        });
    }

    private void startAutoRefresh() {
        handler.postDelayed(new Runnable() {
            @Override
            public void run() {
                if (webView != null) webView.reload();
                handler.postDelayed(this, REFRESH_DELAY);
            }
        }, REFRESH_DELAY);
    }

    private void hideSystemUI() {
        getWindow().getDecorView().setSystemUiVisibility(
                View.SYSTEM_UI_FLAG_IMMERSIVE_STICKY
                | View.SYSTEM_UI_FLAG_LAYOUT_STABLE
                | View.SYSTEM_UI_FLAG_LAYOUT_HIDE_NAVIGATION
                | View.SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN
                | View.SYSTEM_UI_FLAG_HIDE_NAVIGATION
                | View.SYSTEM_UI_FLAG_FULLSCREEN);
    }

    @Override
    protected void onResume() {
        super.onResume();
        hideSystemUI();
        // Start Lock Task (Kiosk) Mode if device owner
        // startLockTask(); 
    }
}

5. Application Class (Multi-Process Fix)

Why: Android 9+ crashes if a background process (like a Receiver) tries to touch the WebView data directory.
Java

// File: app/src/main/java/com/yourcompany/kiosk/KioskApplication.java
package com.yourcompany.kiosk;

import android.app.Application;
import android.content.Context;
import android.os.Build;
import android.webkit.WebView;

public class KioskApplication extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        
        // Fix for Android 9+ "Using WebView from more than one process" crash
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) {
            String processName = android.app.Application.getProcessName();
            if (!getPackageName().equals(processName)) {
                WebView.setDataDirectorySuffix("kiosk_process");
            }
        }
    }
}
